---
description: >-
  A good name tells the reader what a thing is or does, so the reader can skip
  its body. A name is chosen when the code is first written, and the code moves
  on without it. The name drifts into a vague word, a type it no longer holds or
  a role it no longer plays, and every reader opens the body to learn the
  truth. This skill asks the agent to judge each name by one question, does it
  tell the reader what the thing is or does, by the steps below.
---

Judge names:
1. List each name the code defines: files, functions, variables, constants, options and keys.
2. Read each name's uses with its definition hidden.
3. Mark a name bad when a use stops reading true without the definition.
4. Mark a name bad when it misleads about the thing's type or role, or runs longer or shorter than its scope needs.
5. Write each bad name's rename.
6. Return each bad name as its file and line, the evidence and the rename.
